## 数据存储

### 存储路径

**Windows:**
- 账号数据: `%APPDATA%\.kiro-account-manager\accounts.json`
- 应用设置: `%APPDATA%\.kiro-account-manager\settings.json`
- 机器码备份: `%APPDATA%\.kiro-account-manager\machine-guid-backup.json`
- MCP配置: `~/.kiro/settings/mcp.json`
- Steering规则: `~/.kiro/steering/*.md`

**macOS/Linux:**
- 账号数据: `~/.kiro-account-manager/accounts.json`
- 应用设置: `~/.kiro-account-manager/settings.json`
- MCP配置: `~/.kiro/settings/mcp.json`
- Steering规则: `~/.kiro/steering/*.md`

### 账号数据结构

```json
{
  "id": "uuid",
  "email": "user@example.com",
  "label": "账号备注",
  "status": "active",
  "addedAt": "2025/01/01 12:00:00",
  "accessToken": "...",
  "refreshToken": "...",
  "expiresAt": "2025/01/01 13:00:00",
  "provider": "Google",
  "authMethod": "social",
  "tags": ["测试", "主力"],
  "usageBreakdown": {
    "baseLimit": 50,
    "baseCurrent": 20,
    "freeTrialLimit": 50,
    "freeTrialCurrent": 10,
    "freeTrialExpiry": "2025-02-01T00:00:00Z",
    "bonuses": []
  },
  "machineId": "optional-machine-id"
}
```

**字段说明：**
- `machineId`: 可选字段，用于存储账号专属的机器 ID
- 如果设置了 `machineId`，切换到该账号时会自动使用该机器 ID
- 如果未设置，则使用系统默认机器 ID

## 账号类型说明

### Social 账号（Google/GitHub）

- refreshToken 以 `aor` 开头
- 使用 Kiro Desktop Auth API 刷新
- 不需要 clientId/clientSecret
- 有 profileArn 字段

### IdC 账号（BuilderId/Enterprise）

- refreshToken 以 `eyJ` 开头（JWT 格式）
- 使用 AWS OIDC API 刷新
- 需要 clientId、clientSecret、region
- 有 clientIdHash 字段

**Enterprise 和 BuilderId 的区别：**
- 使用完全相同的认证流程和 API
- 唯一区别是 Start URL：
  - BuilderId: `https://view.awsapps.com/start`
  - Enterprise: 用户自定义的 Start URL（如 `https://xxx.awsapps.com/start`）
- 在 `registerClient` 时，Enterprise 会传入 `hasUserProvidedInput: true` 用于友好错误提示

## 从 Kiro 导入功能

### 功能说明

支持从 Kiro IDE 的本地数据库中导入已登录的账号，避免重复登录。

### 实现原理

1. **读取 Kiro CLI 数据库**：
   - 路径：`~/.kiro/cli/kiro-cli.db`（SQLite 数据库）
   - 表：`kiro_auth_token`
   - 字段：`id`, `access_token`, `refresh_token`, `expires_at`, `profile_arn`, `client_id_hash`

2. **解析 JWT Token**：
   - 从 `access_token` 中解析 JWT payload
   - 提取 `email`、`provider`、`auth_method` 等信息

3. **判断账号类型**：
   - 如果有 `profile_arn` → Social 账号（Google/GitHub）
   - 如果有 `client_id_hash` → IdC 账号（BuilderId/Enterprise）

4. **去重检查**：
   - Social 账号：按 `email` + `profile_arn` 去重
   - IdC 账号：按 `email` + `client_id_hash` 去重

5. **导入账号**：
   - 创建新账号记录
   - 自动刷新 Token 获取配额信息
   - 保存到本地数据库

### 相关文件

- `src-tauri/src/kiro_cli_db.rs` - Kiro CLI 数据库读取
- `src-tauri/src/account.rs` - 账号模型和去重逻辑
- `src-tauri/src/commands/account_cmd.rs` - 导入命令实现
- `src/components/features/AccountManager/ImportAccountModal.jsx` - 导入界面

### 使用方式

1. 打开账号管理页面
2. 点击"导入"按钮
3. 切换到"从 Kiro 导入" Tab
4. 点击"检测账号"按钮
5. 选择要导入的账号
6. 点击"导入选中账号"

## 机器 ID 管理

### 功能说明

支持为每个账号设置专属的机器 ID，切换账号时自动更换机器 ID。

### 实现原理

1. **账号专属机器 ID**：
   - 在账号数据中添加 `machineId` 字段（可选）
   - 如果设置了 `machineId`，切换账号时会自动使用该机器 ID
   - 如果未设置，则使用系统默认机器 ID

2. **自动更换机器 ID**：
   - 在设置中开启"切换账号时自动更换机器码"
   - 切换账号时，如果账号有专属机器 ID，则自动更换
   - 如果账号没有专属机器 ID，则生成新的随机机器 ID

3. **机器 ID 存储**：
   - Kiro IDE 机器 ID 存储在 `~/.kiro/cli/kiro-cli.db` 的 `machine_id` 表
   - 系统机器码存储在 Windows 注册表 `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Cryptography\MachineGuid`

### 相关文件

- `src-tauri/src/kiro.rs` - Kiro IDE 集成（读写机器 ID）
- `src-tauri/src/commands/machine_guid/` - 系统机器码管理
- `src-tauri/src/commands/kiro_settings_cmd.rs` - Kiro IDE 设置命令
- `src/components/features/Settings.jsx` - 设置界面

## 开发注意事项

### 1. 账号去重逻辑

**重要**：不同类型的账号使用不同的去重字段！

- **Social 账号**：按 `email` + `profile_arn` 去重
- **IdC 账号**：按 `email` + `client_id_hash` 去重

**错误示例**：
```rust
// ❌ 错误：只按 email 去重
accounts.iter().any(|a| a.email == new_account.email)
```

**正确示例**：
```rust
// ✅ 正确：根据账号类型使用不同的去重逻辑
match new_account.auth_method {
    AuthMethod::Social => {
        accounts.iter().any(|a| {
            a.email == new_account.email && 
            a.profile_arn == new_account.profile_arn
        })
    }
    AuthMethod::Idc => {
        accounts.iter().any(|a| {
            a.email == new_account.email && 
            a.client_id_hash == new_account.client_id_hash
        })
    }
}
```

### 2. JWT Token 解析

从 `access_token` 中解析 JWT payload 时，需要处理 Base64 URL 编码：

```rust
use base64::{engine::general_purpose::URL_SAFE_NO_PAD, Engine};

let parts: Vec<&str> = token.split('.').collect();
if parts.len() != 3 {
    return Err("Invalid JWT format");
}

let payload = URL_SAFE_NO_PAD.decode(parts[1])?;
let json: serde_json::Value = serde_json::from_slice(&payload)?;
```

### 3. 数据库操作

读取 Kiro CLI 数据库时，需要处理 SQLite 连接：

```rust
use rusqlite::{Connection, Result};

let db_path = home_dir()?.join(".kiro/cli/kiro-cli.db");
let conn = Connection::open(db_path)?;

let mut stmt = conn.prepare("SELECT * FROM kiro_auth_token")?;
let rows = stmt.query_map([], |row| {
    Ok(KiroAuthToken {
        id: row.get(0)?,
        access_token: row.get(1)?,
        refresh_token: row.get(2)?,
        expires_at: row.get(3)?,
        profile_arn: row.get(4).ok(),
        client_id_hash: row.get(5).ok(),
    })
})?;
```

### 4. 错误处理

所有 Tauri 命令都应该返回 `Result<T, String>`，并提供友好的错误信息：

```rust
#[tauri::command]
pub fn import_from_kiro() -> Result<Vec<Account>, String> {
    match read_kiro_cli_db() {
        Ok(accounts) => Ok(accounts),
        Err(e) => Err(format!("读取 Kiro 数据库失败: {}", e))
    }
}
```

### 5. 前端调用

使用 `invoke()` 调用 Rust 命令时，需要处理异步和错误：

```javascript
try {
  const accounts = await invoke('import_from_kiro')
  console.log('导入成功:', accounts)
} catch (error) {
  console.error('导入失败:', error)
  toast.error(error)
}
```
